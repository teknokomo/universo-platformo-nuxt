## 📖 О проекте

Universo Platformo Nuxt — это полнофункциональная реализация концепции Universo Platformo с использованием современных веб-технологий. Этот проект предоставляет комплексную платформу для создания взаимосвязанных цифровых пространств, метавселенных и сред для совместной работы.

Это **реализация на Nuxt.js** концепции Universo Platformo, отличающаяся от версии на React, но вдохновлённая ею. Мы используем ту же концептуальную основу, но реализуем её с использованием лучших практик Nuxt.js и полнофункциональных возможностей.

## 🔗 Связь с universo-platformo-react

Этот проект концептуально основан на [universo-platformo-react](https://github.com/teknokomo/universo-platformo-react), который служит **эталонной реализацией** для понимания архитектуры Universo Platformo и набора функций.

**Важные отличия:**

- **Только концептуальная основа**: Мы следуем архитектурным концепциям, связям между сущностями и структуре функций из версии на React
- **Без копирования кода**: Это свежая реализация с использованием лучших практик Nuxt.js/TypeScript, а не перенос кода React
- **Улучшенная реализация**: Мы избегаем копирования устаревшего кода, незавершённых функций или недостатков реализации из версии на React
- **Полнофункциональный подход**: В отличие от версии на React с раздельным frontend/backend, мы используем полнофункциональные возможности Nuxt

**Что мы берём из версии на React:**

- Общую архитектуру проекта и структуру пакетов
- Паттерны связей между сущностями (например, Кластеры/Домены/Ресурсы)
- Объём функций и дорожную карту
- Принципы организации монорепозитория

**Что мы делаем по-другому:**

- Используем Nuxt 3 с TypeScript вместо React
- Реализуем серверный рендеринг и API-маршруты нативно
- Следуем конвенциям и лучшим практикам экосистемы Nuxt
- Используем файловую маршрутизацию вместо React Router
- Реализуем функции постепенно с разработкой на основе спецификаций

## 🚀 Ключевые отличия

### Технологический стек

| Аспект           | Universo Platformo React   | Universo Platformo Nuxt              |
| ---------------- | -------------------------- | ------------------------------------ |
| Фреймворк        | React                      | Nuxt 3 (на основе Vue)               |
| Backend          | Express (отдельные пакеты) | Nuxt Server Routes (интегрированные) |
| Маршрутизация    | React Router               | Файловая маршрутизация               |
| Система типов    | TypeScript                 | TypeScript (строгий режим)           |
| Менеджер пакетов | PNPM                       | PNPM                                 |
| UI-библиотека    | Material UI (React)        | Scoped CSS (Vuetify 3 планируется)   |

### Архитектурный подход

- **Полнофункциональная интеграция**: Nuxt предоставляет интегрированные frontend и backend в одном фреймворке
- **Серверный рендеринг**: Нативная поддержка SSR из коробки
- **API-маршруты**: Серверные endpoints расположены рядом со страницами
- **Лучшие практики**: Реализация следует паттернам и конвенциям экосистемы Nuxt

## 🛠 Технологический стек

### Основные технологии

- **Фреймворк**: [Nuxt 3.x](https://nuxt.com/) - Полнофункциональный Vue-фреймворк с SSR
- **Язык**: [TypeScript 5.x](https://www.typescriptlang.org/) - Строгий режим включён
- **Менеджер пакетов**: [PNPM 8.x+](https://pnpm.io/) - Быстрый, эффективно использующий дисковое пространство
- **База данных**: [Supabase](https://supabase.com/) - На основе PostgreSQL с возможностями realtime
- **Аутентификация**: [Supabase Auth](https://supabase.com/docs/guides/auth) - Только на сервере, через HTTP-only куки
- **i18n**: [@nuxtjs/i18n](https://i18n.nuxtjs.org/) - Английский + русский с управлением пространствами имён

### Качество кода

- **Линтинг**: ESLint с правилами TypeScript и Nuxt
- **Форматирование**: Prettier для единообразного стиля кода
- **Проверка типов**: Компилятор TypeScript в строгом режиме
- **Тестирование**: Vitest (стандарт экосистемы Nuxt/Vite)

### Стратегия работы с базой данных

- **Основная база данных**: Supabase с Row Level Security (RLS)
- **Слой абстракции**: Паттерн репозитория для обеспечения будущих миграций баз данных
- **Управление схемой**: Миграции под контролем версий
- **Прямой доступ запрещён**: Все операции с базой данных через слой абстракции

### Конвенции структуры пакетов

Все пакеты функций следуют единообразной структуре:

- **Frontend-пакеты**: Используют суффикс `-frt` (например, `packages/clusters-frt`)
- **Backend-пакеты**: Используют суффикс `-srv` (например, `packages/clusters-srv`)
- **Utility-пакеты**: Используют scope `@universo/` (например, `@universo/types`, `@universo/utils`)
- **Папка base**: Каждый пакет содержит корневую папку `base/` для поддержки будущих множественных реализаций
- **Разделение**: Frontend и backend — отдельные пакеты, когда требуются оба
- **Односторонние пакеты**: Если функции нужен только frontend или только backend, создаётся только этот пакет

**⚠️ КРИТИЧНО: ВЕСЬ код функционала ДОЛЖЕН быть в пакетах**

- ❌ **ЗАПРЕЩЕНО**: Создание кода функционала в корневых директориях (`src/`, `components/`, `pages/`, `server/`)
- ✅ **ТРЕБУЕТСЯ**: Весь функционал реализован внутри директории `packages/`
- ✅ **РАЗРЕШЕНО**: Только конфигурационные файлы, документация и минимальная загрузка в корне

Это строгое требование гарантирует, что пакеты могут быть извлечены в отдельные репозитории в будущем.

**Примеры структур пакетов:**

```
packages/clusters-frt/base/   # Frontend: UI управления кластерами
packages/clusters-srv/base/   # Backend: API кластеров и бизнес-логика
packages/@universo/types/base/  # Общие: Определения типов TypeScript
```

## 📦 Категории пакетов и система нод

Этот монорепозиторий организует функциональность в отдельные категории пакетов, каждая из которых служит определённой цели в экосистеме Universo Platformo.

### Основные пакеты функций

Основные функции следуют единообразному паттерну разделения **frontend + backend** с суффиксами `-frt` (frontend) и `-srv` (server/backend):

- **`auth-frt` + `auth-srv`**: Система аутентификации с логином, регистрацией и управлением сессиями
- **`clusters-frt` + `clusters-srv`**: Управление Кластерами/Доменами/Ресурсами (основа паттерна трёх сущностей)
- **`metaverses-frt` + `metaverses-srv`**: Управление Метавселенными/Секциями/Сущностями (репликация паттерна трёх сущностей)
- **`uniks-frt` + `uniks-srv`**: Управление рабочими пространствами (концептуальный эквивалент организаций)
- **`spaces-frt` + `spaces-srv`**: Визуальный редактор потоков для Spaces/Canvases с композицией на основе нод
- **`space-builder-frt` + `space-builder-srv`**: Конструктор пространств с AI, использующий интеграцию с LLM для генерации потока из промпта
- **`publish-frt` + `publish-srv`**: Система публикации и экспорта приложений
- **`profile-frt` + `profile-srv`**: Управление профилем пользователя и настройками
- **`projects-frt` + `projects-srv`**: Управление проектами внутри рабочих пространств
- **`storages-frt` + `storages-srv`**: Хранение файлов и управление ресурсами

### Система нод

Universo Platformo включает мощную **систему композиции на основе нод** для создания интерактивных пространств и рабочих процессов на базе AI:

#### UPDL ноды (`updl/base`)

**Universal Platform Description Language (UPDL)** определяет основные типы нод:

- **Entity Nodes**: Представляют объекты и акторов в системе
- **Component Nodes**: Модульные поведения и свойства, прикрепляемые к сущностям
- **Action Nodes**: Исполняемые операции и трансформации
- **Event Nodes**: Реактивные триггеры и обработчики событий
- **Data Nodes**: Источники данных и коннекторы хранилищ
- **Space Nodes**: Пространственные отношения и иерархии
- **Universo Nodes**: Межпространственные и мета-уровневые операции

#### Библиотека компонентов нод (`node-components/base`)

Комплексная библиотека готовых нод для быстрой разработки:

**Ноды интеграции с LangChain:**

- **LLM Nodes**: ChatOpenAI, ChatAnthropic, ChatGoogle, поддержка локальных моделей
- **Chain Nodes**: LLMChain, SequentialChain, ConversationChain для сложных рабочих процессов
- **Agent Nodes**: OpenAI Functions Agent, ReAct Agent, Plan-and-Execute Agent
- **Tool Nodes**: Calculator, WebBrowser, интеграции Custom API, SerpAPI, Wikipedia
- **Memory Nodes**: BufferMemory, ConversationSummary, персистентность Redis, PostgreSQL
- **Vector Store Nodes**: Pinecone, Supabase Vector, Chroma, FAISS для семантического поиска
- **Embeddings Nodes**: OpenAI Embeddings, HuggingFace, Cohere для векторизации текста
- **Document Loader Nodes**: PDF, CSV, JSON, Web Scraper, интеграция с Notion API
- **Text Splitter Nodes**: Стратегии разделения по символам, рекурсивное, на основе токенов
- **Cache Nodes**: InMemory, Redis, Upstash для оптимизации производительности
- **Output Parser Nodes**: Структурированный вывод, парсинг списков, форматирование DateTime

**Кастомные AI ноды:**

- Специфичные для Universo интеграции с AI
- Адаптированные под предметную область языковые модели
- Кастомные шаблоны промптов и цепочки

**Ноды обработки данных:**

- Операции Transform, Filter, Aggregate
- Валидация и санитизация данных
- ETL-пайплайны

**Ноды интеграции:**

- Коннекторы внешних API
- Ноды запросов к базе данных
- Потоки данных в реальном времени

### Общие утилиты

Централизованные пакеты утилит со скоупом `@universo/` предоставляют переиспользуемую функциональность для всех функций:

- **`@universo/types`**: Общие TypeScript интерфейсы, типы и type guards
- **`@universo/utils`**: Общие утилитарные функции, хелперы и алгоритмы
- **`@universo/api-client`**: Типобезопасная библиотека API-клиента для коммуникации с backend-сервисами
- **`@universo/i18n`**: Централизованная интернационализация (английский + русский) с управлением пространствами имён
- **`@universo/template-vuetify`**: Библиотека компонентов Vuetify 3, темы и расширения Material Design
- **`@universo/rest-docs`**: Генератор документации REST API

### Шаблоны пакетов

Готовые к использованию шаблоны для создания специализированных пространств и приложений:

- **`template-mmoomm/base`**: Шаблон MMO на основе PlayCanvas для многопользовательских 3D-пространств
- **`template-quiz/base`**: Шаблон викторины на основе AR.js для приложений дополненной реальности
- **Будущие шаблоны**: Дополнительные шаблоны будут добавляться на основе потребностей сообщества и use cases

Каждый шаблон предоставляет полную отправную точку с предварительно сконфигурированными нодами, UI-компонентами и backend-логикой.

### Принципы организации пакетов

Все пакеты следуют единообразным принципам:

1. **Разделение ответственности**: Frontend и backend всегда являются отдельными пакетами, когда нужны оба
2. **Конвенция папки base**: Каждый пакет содержит директорию `/base/` для будущей поддержки множественных реализаций
3. **Независимость**: Пакеты должны быть извлекаемыми в отдельные репозитории с минимальными изменениями
4. **Управление зависимостями**: Общий код находится в пакетах утилит `@universo/*`, не дублируется
5. **Единообразие именования**: Понятные, описательные имена с суффиксами `-frt`/`-srv` или скоупом `@universo/`

## 🏗 Паттерн трёх сущностей

Universo Platformo построен на гибком **паттерне трёх сущностей**, который повторяется в различных функциональных доменах:

### Базовый паттерн: Кластеры

Базовая реализация использует:

- **Кластеры**: Организационные единицы верхнего уровня
- **Домены**: Группировки среднего уровня внутри кластеров
- **Ресурсы**: Отдельные элементы внутри доменов

### Репликация паттерна

Та же трёхуровневая иерархия реплицируется в различных функциях:

- **Метавселенные** → **Секции** → **Сущности**
- **Пространства** → **Холсты** → **Узлы** (для функций на основе графов)
- **Другие домены**, следующие аналогичным паттернам

Каждый домен может адаптировать этот паттерн с доменно-специфической логикой, сохраняя при этом базовую трёхуровневую структуру. Некоторые функции могут использовать частичные паттерны (2 уровня) или расширенные паттерны (4+ уровня) по мере необходимости.

## 🚀 Начало работы

### Предварительные требования

- **Node.js**: LTS версия 18.x или выше
- **PNPM**: Версия 8.x или выше

Для глобальной установки PNPM:

```bash
npm install -g pnpm
```

### Установка

1. **Клонировать репозиторий**:

```bash
git clone https://github.com/teknokomo/universo-platformo-nuxt.git
cd universo-platformo-nuxt
```

2. **Установить зависимости**:

```bash
pnpm install
```

### Команды для разработки

```bash
# Установить все зависимости
pnpm install

# Режим разработки (после реализации функций)
pnpm dev

# Сборка для production (после реализации функций)
pnpm build

# Проверка типов
pnpm typecheck

# Линтинг
pnpm lint
pnpm lint:fix

# Форматирование кода
pnpm format
pnpm format:check

# Выполнить все проверки качества кода
pnpm quality
```

## 📦 Создание нового пакета

Для создания нового пакета функции, следуя конвенциям проекта:

1. **Создать директорию пакета**:

```bash
mkdir -p packages/{domain}-{frt|srv}/base
```

2. **Создать package.json**:

```json
{
  "name": "@universo/{domain}-{frt|srv}",
  "version": "0.1.0",
  "private": true
}
```

3. **Создать двуязычные README-файлы**:

- `README.md` (английский, основной)
- `README-RU.md` (русский перевод с идентичной структурой)

4. **Установить рабочее пространство**:

```bash
pnpm install
```

**Предполагаемое время**: Менее 10 минут, следуя этому руководству.

**Метки типов** (Обязательны для всех issues/PRs):

- `type:feature` - Новый функционал или возможности
- `type:bug` - Что-то работает некорректно
- `type:docs` - Улучшения или дополнения к документации
- `type:refactor` - Реструктуризация кода без изменения функциональности
- `type:chore` - Задачи обслуживания, обновления зависимостей и т.д.

**Метки областей** (Применяются по мере необходимости):

- `area:infrastructure` - Настройка репозитория, системы сборки, развёртывание
- `area:clusters` - Функциональная область кластеров
- `area:metaverses` - Функциональная область метавселенных
- `area:auth` - Аутентификация и авторизация
- Дополнительные метки областей добавляются по мере реализации функций

**Метки приоритетов** (Опционально, наследуются из Issue при необходимости):

- `priority:P1` - MVP, обязательно для первого релиза
- `priority:P2` - Важно, должно быть реализовано в ближайшее время
- `priority:P3` - Желательно, может быть отложено

**Метки статуса** (Опционально, для управления рабочим процессом):

- `status:blocked` - Невозможно продолжить из-за внешней зависимости
- `status:in-progress` - В процессе разработки
- `status:review` - Ожидает code review

Полные руководства по меткам см. в [.github/instructions/github-labels.md](./.github/instructions/github-labels.md).

## 📚 Документация и управление

### Конституция проекта

Этот проект следует строгим принципам управления, определённым в [.specify/memory/constitution.md](./.specify/memory/constitution.md).

**Ключевые принципы:**

1. **Архитектура монорепозитория**: Все пакеты в одном репозитории с PNPM
2. **Разработка на основе спецификаций**: Каждая функция начинается с полной спецификации
3. **Двуязычная документация**: Вся документация на английском и русском (ОБЯЗАТЕЛЬНО)
4. **Единообразие технологического стека**: Основные технологии обязательны для всех пакетов
5. **Инкрементальная разработка**: Функции строятся с независимыми, тестируемыми пользовательскими историями (P1→P2→P3)
6. **Соответствие эталону**: Следуем концепции React, реализуем с лучшими практиками Nuxt
7. **Организация пакетов утилит**: Общий код в централизованных пакетах утилит
8. **Применение паттерна Repository**: Весь доступ к базе данных через репозитории TypeORM
9. **Универсальная система ролей**: Единая иерархия ролей во всех функциях

### Архитектурные паттерны

Детальные архитектурные паттерны, принятые из Universo Platformo React:

- **English**: [.specify/memory/architectural-patterns.md](./.specify/memory/architectural-patterns.md)
- **Russian**: [.specify/memory/architectural-patterns-RU.md](./.specify/memory/architectural-patterns-RU.md)

**Ключевые паттерны:**

- **Паттерн Repository**: Все операции с базой данных через TypeORM (без прямого SQL)
- **Паттерн Guards**: Централизованная проверка разрешений с фабричными функциями
- **Фабричные функции**: Переиспользуемые генераторы actions, сокращающие дублирование кода на 90%+
- **Универсальная система ролей**: owner > admin > editor > member > guest
- **Архитектура i18n**: Централизованная регистрация пространств имен
- **Паттерн Universal List**: Переиспользуемые компоненты списков с пагинацией на бэкенде
- **Интеграция RLS**: Row Level Security с валидацией на уровне приложения
- **Изоляция данных**: Трехуровневая изоляция с промежуточными таблицами

### Требования к двуязычной документации

**Вся документация ДОЛЖНА быть предоставлена на английском и русском языках:**

1. **Английский — основной**: Сначала создаётся документация на английском
2. **Немедленный перевод**: Русская версия должна быть создана сразу после английской
3. **Идентичная структура**: Обе версии должны иметь одинаковое количество строк, одинаковые разделы
4. **Именование README**: Русские версии используют суффикс `-RU.md` (например, `README-RU.md`)
5. **Issues/PRs**: Используйте формат спойлера `<summary>In Russian</summary>` (точный тег)

См. [.github/instructions/i18n-docs.md](./.github/instructions/i18n-docs.md) для полного руководства.
